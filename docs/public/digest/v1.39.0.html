v1.39.0

Your own database servers, and plugins that run on their own

A database server lerd does not run is now a service of its own, so DBngin or a native MySQL gets snapshots, restore, the shell and worktree isolation like lerd's own. Plugins can run on a schedule once you allow it, keep their tab to sites with a database, and open the dashboard's diff and editor. This is also the first signed release, PHP 8.6 leaves the prerelease tier, the dashboard counts and applies PHP, Node and tool updates, and lerd has a new face, a stack of containers.

01

Databases

FEAT

A MySQL, MariaDB or PostgreSQL server lerd does not run, such as DBngin or one installed with the system, is added as a service with lerd service external or from Add a service. A site pointed at it gets the database features lerd has, through the machine's own clients. #2449

AN EXTERNAL SERVERthe server's data is never touched by removing it
1
Add the server

lerd tests the password and finds mysql, mysqldump, psql and pg_dump on the PATH or in a folder given with --tools before it saves anything.

2
Point a site at it

lerd db:use <service> rewrites the env by what each key means, so separate keys, a host:port value and a connection URL all work.

3
Use it like lerd's own

Snapshots manual and automatic, restore, export, import, the shell, browsing, the assistant tools and worktree isolation run against it.

FEATUI

A page of its own #2449

The server gets Databases and Snapshots like lerd's own services, and the + beside its site count points another site at it.

FEAT

Offline, said once #2449

A server that stops answering shows offline and notifies once, and passwords stay out of .lerd.yaml.

SAFE

No falling through #2449

A command that cannot work on a site's server refuses instead of reaching lerd's own database.

02

Plugins

FEATFIX

A plugin can declare schedules, each naming an executable and how often it runs, and lerd-ui runs them once you allow it, so a plugin never installs a cron job or timer of its own. #2554

A SCHEDULEnothing runs until it is allowed
1
Asked once

At install, or at the update that adds or changes a schedule, in the terminal or on the Plugins page.

2
Run on time

lerd remembers the last run across restarts, runs once after a sleep that skipped its time, and never starts a second run while one is going.

3
Shown and switched

The plugin's card and lerd plugin schedule <name> show the interval, the last run and the next, and on or off changes the answer.

FEATUI

A tab where it belongs #2546 #2559

A plugin's tab can be hidden on one site, and a tab that says when: database shows only on sites that point at a database. The plugin menu leaves out a switch that cannot show.

FEATUI

The dashboard's diff and editor #2514 #2518

Plugin pages call lerd.diff and lerd.view for the same Monaco modal as the git diff, and lerd.edit hands the saved text back to the page.

FIX

A tab no longer wakes the site #2563

Plugins run through lerd's node and php shims, which counted as working on the site. A plugin's runs leave the site's workers asleep now, and the services its code needs still start.

03

Updates

FEATUI

The System health card counts PHP and tool updates next to service ones, each with an Update all dialog that has a switch per item. PHP images rebuild together and restart in turn, tools update one at a time, and a failure is named without stopping the rest. #2436

FEATUI

Node to its newest patch #2442

The Node page shows the full version behind each major and compares it with nodejs.org. lerd node:update does the same, and a new major is never offered.

FEAT

PHP 8.6 is released #2470

A bare lerd fetch builds it with the others. FrankenPHP and a few extensions have not caught up, so an 8.6 site stays on FPM with a message saying why.

FEAT

wp-cli without composer #2511

The first lerd wp on a WordPress site with no vendor/bin/wp downloads the wp-cli release lerd pins, checks its sha256, and lists it on the Tools page.

04

Signed releases

SEC

Each release's checksums.txt is signed with cosign in keyless mode, tied to the release workflow, and each archive carries a build provenance attestation. A download can now be checked for who built it as well as whether it arrived whole. #2491

shell
cosign verify-blob checksums.txt \
  --bundle checksums.txt.sigstore.json \
  --certificate-identity-regexp '^https://github.com/lerd-env/lerd/\.github/workflows/release\.yml@refs/tags/v' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
gh attestation verify lerd_1.39.0_linux_amd64.tar.gz --repo lerd-env/lerd
05

New look

FEATUI

The red L gives way to a stack of isometric containers designed by @claxonberlin, on the dashboard, the docs, lerd.sh, the favicon, the launcher icons and notifications, with a light and a dark palette where the theme is known. #2545

FEAT

A tray that shows the state #2545

The tray draws the same containers and strikes them through while lerd is stopped, mono mode slashes its silhouette the same way, and high contrast keeps its green and red icons.

FEAT

A start you can see #2544

The item reads Starting Lerd while the command runs and cannot be clicked twice, the icon blinks until it ends, and the result shows at once.

FEAT

A name for the site #2525

An optional app_name in .lerd.yaml titles the site on the dashboard and in the TUI, so a plain PHP site can show more than its domain, contributed by @HuntiXz.

06

Lighter

REF

A service now starts once however many lerd processes ask for it. db:shell, a php run, a site's link and an env write ask the watcher, which starts it and runs one probe loop for them all. #2562

FIX

A bounded debug buffer #2561

Requests kept as a route's slowest had no cap together, and one app grew the file to 2.8 GB. Kept requests now share the buffer size, and a grown file gets its disk back.

REF

One launchctl list on macOS #2420

One shared list replaces a fork per unit, taking an open site page from about 1,600 launchctl calls in 30 seconds to about 10, contributed by @prabowosd.

REF

Cheaper dashboard snapshots #2423 #2421

Framework definitions are kept for three seconds and the site header stops rereading git status, which halved lerd-ui's CPU with a site page open, contributed by @prabowosd.

07

More

FEATUI

A worker's proxy can take a subdomain of its site, so a docs dev server in the same repository gets docs.myapp.test without a second site, through the site's certificate and with WebSocket upgrades for HMR, contributed by @ExeQue. #2444

FEATUI

Stage a whole section #2464

Staged, Unstaged and Untracked each get a button for all of their files, and each file shows the lines it adds and removes. A diff split dragged by hand stays put from file to file.

FEAT

MCP offered at install #2505

lerd install and lerd update ask once whether to connect lerd to the AI assistants on the machine, and a no is remembered. A run without a terminal is never asked.

FEAT

Exits that are an answer #2500

A plugin command lists the exits its tool answers with, like 101 from cargo check, without failing the plugin, contributed by @mtolhuys.

08

Fixes

FIX

The fixed list covers bugs that shipped in 1.38 or earlier. Several came from the release lanes, which ran this release on Ubuntu, Fedora, Silverblue, Bazzite, Omarchy and Windows.

FIX

An update that stopped halfway #2552

The dashboard and tray opened lerd update inside the service it restarts, so systemd killed it. The terminal runs in a scope of its own now.

FIX

A symlinked home folder #2551

On Bazzite, where /home links to /var/home, unpark left sites linked and lerd php missed the provided env.

FIX

nginx restarted on each install #2521

Each restart took the sites down for a moment, and a taken port 80 left them dark. Install reloads nginx unless something changed.

FIX

Dev servers on the Wi-Fi address #2502

The fallback exposed them on the network and moved with it. lerd tries its own lerd0 address first, contributed by @mtolhuys.

FIX

A service a pull added #2507

A service a git pull added to .lerd.yaml showed on the site while .env never got its connection. The watcher wires it now.

FIX

The Podman Machine went down #2522

On macOS the VM shared the process group of whatever started it, so closing that terminal stopped all of its containers.
